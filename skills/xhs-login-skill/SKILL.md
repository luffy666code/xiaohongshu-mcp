## 执行流程

### 1. 检查登录状态

调用 `check_login_status`（无参数），返回是否已登录及用户名。

- 已登录 → 告知用户当前登录账号
- 未登录 → 进入步骤 2

### 2. 扫码登录

调用 `get_login_qrcode`（无参数）。

**工具会弹出一个真实浏览器窗口停在小红书登录页，并一直阻塞到扫码完成**——默认最多等 120 秒，可用 `timeout_seconds` 调整（30–900）。你只需要告诉用户「浏览器窗口已打开，请用小红书 App 扫码」。

- 扫码成功后窗口**自动关闭**，工具返回「✅ 已登录」。**登录态此时已保存，不需要再调用 `check_login_status` 确认。**
- 返回「❌ 未完成登录」说明等待超时（窗口会一并关闭），可再次调用本工具重试。

**关于二维码**：默认是有头模式，二维码就显示在浏览器窗口里，**不要把它转成图片或 Base64 交给用户**。只有在无法开窗的纯无头环境下才传 `headless: true`，此时工具返回 PNG 格式二维码（MCP image content type，Base64 编码），客户端直接渲染即可；若客户端无法显示图片，可把 Base64 存成临时 PNG 文件让用户打开。

> 等待扫码期间这个调用会一直阻塞，不要以为它已经结束而去调其他工具（同一个浏览器数据目录同一时刻只能被一个浏览器实例使用）。

### 3. 重新登录 / 切换账号

当用户要求重新登录或切换账号时：

1. 调用 `delete_cookies`（⚠️ 需用户确认）— 重置登录状态
   - 它会**同时清掉 cookies 文件和浏览器数据目录**（登录态主要存在后者），所以切换后不会残留上一个账号的信息；设备指纹 seed 会保留
   - 用户**不需要**手动删文件，也**不需要**重启 MCP 服务
2. 调用 `get_login_qrcode` — 打开窗口让用户扫新账号的二维码
3. 扫码成功后即可继续使用其他工具

> 重要：如果当前已经登录，直接调 `get_login_qrcode` 不会覆盖已有账号，它会返回「已登录」并**不打开扫码窗口**——所以切换账号必须先调 `delete_cookies`。

## 约束

- `delete_cookies` 会清除登录状态，执行前必须确认
- 登录需要用户手动用手机 App 扫码，无法自动完成

## 失败处理

| 场景 | 处理 |
|---|---|
| MCP 工具不可用 | 引导用户使用 `/setup-xhs-mcp` 完成部署和连接配置 |
| 二维码/登录页出不来，提示「IP存在风险」 | 这是站点风控，不是工具故障；提示用户更换网络环境后重试 |
| 等待扫码超时 | 重新调用 `get_login_qrcode` |
